# EvidenceBench-Assisted Adaptation

Upstream: [EvidenceBench, COLM 2025](https://github.com/EvidenceBench/EvidenceBench). Pinned version: `bf1d9633c694381c7b016fd56ee9f95f48593cc3`. The adapter verifies the official files’ Git blob SHA1 and records SHA256; it does not reassign source-sentence indices.

The current run uses the original development set of 37 papers and 6310 sentences, returns a fixed 10 sentences, and measures coverage across different evidence aspects. Labels are passed only to the evaluator after selection; the model input consists only of the hypothesis, source text, and candidate sentences. This task is not author identification, expert ranking, or an assessment of industrial applicability. Upstream labels are provided by an expert-guided generation and validation process; they are not described as a new, entirely human-produced gold standard created by us.

The original dev set retains the upstream CC-BY-NC-SA license, and the original test set retains the upstream CC-BY license; source data are not included in this project’s source-code review package. The current test set was not used to adjust the rules; `prepare('test')` only provides an entry point for obtaining a pinned version.

- BM25/Qwen/fixed MMR aspect coverage: 0.3375/0.4770/0.4599.
- Qwen top 30 sentences + native Decisions: 0.5619, 37 valid cases.
- Closed-set chat selection over the same candidates: 0.5904, 35 valid cases, with 2 cases counted as semantic fallbacks.

All results are development-stage auxiliary results, not a complete reproduction of a published paper, a new SOTA, or a new metric. The two types of model selection have different objectives, and the interface execution order does not constitute randomly paired latency measurement. Independent relevance probabilities cannot substitute for set complementarity; the subsequent role-compilation hypothesis still requires independent testing.

Source-role compilation v1 (fixed rules, all 37 papers): compilation input was source text only; complete numbered partitioning was valid for 9 papers and fell back for 28, with aspect coverage of 0.4826, +0.0056 over Qwen in the same run, and a 95% bootstrap interval of [-0.0312,0.0402]. Offline compilation took 139.08 seconds. Failures were primarily duplicate/omitted sentence IDs; there was no retry, repair, or deletion. This is not included in the default method, and no claim is made that quality is preserved or that end-to-end speed is improved. Results are in `artifacts/evidencebench-role-index-v1/summary.json`.

Conservative normalization development diagnostic v1: duplicates within the same role were deduplicated; 169 cross-role conflicts and 46 omissions were both marked uncertain; invalid IDs or incorrect structures still caused a full-paper fallback. The original source compilation responses were reused; the model was not retried, and queries were not read to repair roles. All 37 papers could be normalized, with aspect coverage of 0.5580; +0.0809 relative to Qwen in the same run, with a 95% bootstrap interval of [0.0209,0.1442]. These rules were devised after observing development-set structural failures and cannot be described as independent validation. Mean online query encoding, ranking, and role-priority ordering time was 42.25 milliseconds; offline model time was 139.08 seconds; timing comparisons with previous interfaces were not randomly paired. The original test set of 293 papers has been fixed under the same rules; the protocol is `artifacts/evidencebench-role-test-v1/protocol.json`, and results follow below.

Fixed original test results: 293 queries/284 papers; 291 queries could be normalized and 2 fell back; aspect coverage was 0.4935, versus 0.4324 for Qwen, a difference of +0.0611, with a paper-grouped bootstrap interval of [0.0377,0.0840]. Per-query metrics and role normalization were independently recomputed; the intersection of development/test paper IDs, complete source texts, and exact hypotheses was 0; no near-duplicate audit was performed. Query encoding and ranking/role selection on an RTX5090 took 8.35 milliseconds, excluding initialization and source-vector loading/building; four concurrent offline API requests took a cumulative 1162.77 seconds, not wall-clock time or an end-to-end gain. Both the vector job (39289) and evaluation job (39292) completed with status 0:0. This result supports only improved auxiliary evidence selection; it does not establish enterprise expert ranking or the originality of a new method. The complete protocol and audit are in `artifacts/evidencebench-role-test-v1/`.

A post-hoc audit of the same frozen selections calculates the fraction of ten selected sentences that cover at least one original annotated aspect. Its mean is 0.395 for role priority versus 0.336 for Qwen, with a paper-cluster paired difference of +0.059 and interval [0.042, 0.076]. For 288 queries with nonempty results-aspect inventories, corresponding results-aspect recall is 0.594 versus 0.496, difference +0.099 and interval [0.067, 0.132]. These are original model-assisted aspect labels; the sentence measure is not fact-checking, personal attribution, or a human gold precision score. Both metrics were chosen after the test, bootstrap intervals are unadjusted for multiple analyses, and five empty/missing results-aspect inventories are excluded only from that second metric. `experiments.retrieval.evidencebench_precision_audit` recomputes them from frozen selections and source labels.

An after-the-fact reuse audit finds eight repeated-paper groups covering 17 test queries; sentence snapshots are identical within each group, but the original protocol compiled each query's source independently. All ten possible pairs had valid normalized compilations. None had identical full role assignments or identical preferred-sentence sets; the mean Jaccard overlap of preferred sets was 0.917. This small post-hoc audit measures output stability, not correctness. The source-only audit is `experiments.retrieval.audit_role_reuse` and local checksums are in `artifacts/evidencebench-role-reuse-audit-v1/`.

The experimental `expert_search.owned_role_windows` adapter binds normalized source-role hints to the source ID, expert ID, exact text hash and fixed window width. It reranks a complete supplied window ordering and returns original text with offsets and ownership; missing, malformed or stale role records fall back to the original ordering. It does not generate the role hints or validate their meaning. Fixed-width windows differ from EvidenceBench's sentence inventory, and neither the reported benchmark gains nor any expert-fit claim has been established for this adapter. Treat it as a testable integration point, not a production default.

`expert_search.owned_role_compile` now offers a query-independent `gpt-6-luna` role-hint call for fixed-width owned windows. A deterministic development pilot selected 12 distinct first-retrieved source views from four enterprise needs and capped each view at 6,000 characters: ten were profiles and two papers. All 12 returned structurally normalizable responses, but normalization found four cross-role conflicts. Of 22 windows, zero were labeled method, zero result, one interpretation, five background, twelve other, and four uncertain. Role priority changed none of the sources' original window order. Average offline request time was 1.52 seconds with complete reported usage, but this tiny, profile-heavy, nonrandom sample does not measure semantic accuracy or amortization. It gives no reason to claim that the EvidenceBench role result transfers to enterprise sources. Original source views and outputs remain local in `artifacts/owned-role-compile-pilot-v1/`.

A separate paper-only follow-up selected 12 retrieved paper views after seeing the profile-heavy sample. All responses were structurally normalizable, with 16 conflicting windows marked uncertain. The 35 windows comprised five method, eight result, three interpretation, three background, zero other and 16 uncertain; four source-order rankings changed under role priority. Average request time was 1.63 seconds with usage present. These are nonrandom, post-hoc, same-model structural counts, not independent role accuracy or an evidence-selection gain.

An additional native Decisions API run classified the same 35 windows using one fixed choice per window and `gpt-6-luna`. All 12 source requests returned valid answers; the format precludes structural multi-role conflicts but does not establish semantic correctness. Chat and Decisions assigned identical normalized labels to 17 of 35 windows. Decisions marked three uncertain; of Chat's 16 uncertain windows, Decisions chose method, result or background for 13. Mean request times were 1.63 and 0.77 seconds respectively; mean reported input tokens were 574 and 1,098, and the Decisions API reported zero output tokens. The runs were sequential, prompts and interfaces differed, and the sample was selected post-hoc; no causal speed, billing, calibration or correctness conclusion follows. The existing model-blind human review remains necessary to resolve these disagreements. Local records are in `artifacts/owned-role-decision-pilot-v1/`.

A post-hoc choice-order check made one forward and one reverse-order Decisions request for each of the same 12 paper views, with randomized order within each pair. All 24 calls succeeded. Twelve of 35 window labels differed between orders; only four of 12 source assignments were identical. An earlier sequential forward-order run also differs from the new forward run on four of 35 windows. The earlier comparison was not randomized or contemporaneous, and its request structure was reconstructed from frozen code rather than saved wire payload. These observations include model/request variability and do not establish a causal order effect or identify correct labels. The human review packet remains unjudged. Local records are in `artifacts/owned-role-order-pilot-v1/`.

`experiments.retrieval.analyze_role_order_windows` reconstructs the source selection and replays the two native role assignments over a deterministic lexical window ordering based on unique query-token overlap. Both role versions change the lexical top window in two of 12 sources, and their selected top windows differ from each other in two sources. This deliberately simple window-ordering control is not the production retriever, and the two outputs cannot be labeled right or wrong without human evidence review. It shows a downstream selection difference in this small development sample; model/request variation remains entangled with choice order.

An agreement-gated role record retains a role only where the forward and reverse choices agree; disagreement becomes uncertain. In a post-hoc replay of the same 12 sources, 12 of 35 windows disagreed and the combined records contained 15 uncertain windows. The combined rule is symmetric under swapping the two inputs, but it changed the lexical top window in three sources and differed from each single-order result in one. The 24 recorded request durations summed to 47.28 seconds, excluding all other work. Same-model agreement is not independent verification, and this replay provides no evidence that the combined selections are more accurate or worth their cost. The control does not use the production retriever. Code is `expert_search.owned_role_consensus` and `experiments.retrieval.replay_role_consensus`.

The local `experiments.retrieval.export_owned_role_review` packet deduplicates the two pilots into 22 source views and 53 windows, hides model labels, and includes full view context and immutable window offsets. Each independent reviewer should label every window `method`, `result`, `interpretation`, `background`, `other`, `mixed`, or `uncertain`, give a reason, and record a reviewer ID. `mixed` preserves cases with multiple roles rather than forcing an arbitrary single label. Source text may expose identity despite hidden IDs; reviewers should not see the private mapping. Validate a reviewer copy with `python -m experiments.retrieval.check_owned_role_review ROOT REVIEW_COPY`, preserve reviewers separately, and adjudicate disagreements independently. All 53 human judgments are currently missing. The packet contains private source text and is not part of the public archive.
