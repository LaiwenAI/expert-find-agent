# Evidence-Based Expert Search：面向企业需求的可追溯能力推断与低延迟排序

**历史研究日志 v2；当前正文见 [研究初稿 v3](draft-v3.md)。本文件保留按时间积累的历史状态，其中早期Decisions不可用等判断已被后续实测更新。目标方向 SIGIR / WWW。本文是一份可复现实证研究稿，尚未证明完整系统同时取得显著精度优势与端到端效率优势。**

## 摘要

面向企业技术需求的专家搜索需要同时完成候选排序、证据定位与能力适用性判断。论文主题相近不等于能够解决目标问题，而缺少相同应用经历也不等于不能迁移已有方法。本文研究一个无需模型训练的粗到细原型：离线构建可追溯的专家问题—方法—对象目录，保留论文及简介原文回退；在线先缩小专家与证据范围，再分别判断事实支持、方法迁移及未覆盖需求。数据构造使用真实需求锚点与同一专家论文，独立审查生成条件，并用真实来源替换形成支持／资料不足控制对。评价协议区分范围保真、关系支持、适用性和时间预算，避免把引用存在或窄能力支持误写为完整项目成功。当前实证包括10673位教师的来源库、9861个可用粗根节点、21位教师的95个语义目录节点及公开专家检索强基线。候选来源读取由约347ms降至中位1.44ms；全库单根向量查询编码与评分均值约28ms，但两个已知银标正例排名为791和5，尚不能安全硬剪枝。95个目录节点中70个获模型引文支持；新的来源替换流程得到四对双模型银标控制，但不构成人工金标准。结果为来源化多分辨率路由提供可复查原型，同时表明稀有能力覆盖、标注有效性和完整系统精度仍是未解决问题；目前尚未证明超越强基线的综合优势。

## 1. 引言

企业技术需求经常同时规定研究对象、技术路线、应用条件与性能指标。例如，专家分别研究材料配方和结构监测，并不能直接证明其具备将两者部署为一体化工程方案的经验。反过来，个人主页未记载某项经验，也不能被解释为实际不具备该能力。面向这一场景，系统应返回排序与支持来源，并保留尚未解决的条件。

我们以三个问题组织研究。第一，在冻结模型与索引条件下，能否减少在线检索和核验工作而维持有效的结果质量？第二，如何从真实需求与教师资料构造可检查的合成任务，同时避免把窄化子任务误标为原需求的完整解决方案？第三，评价应如何同时反映原子条件、关系条件和用户等待时间？

本文保留已有有效组件，包括词法检索、冻结嵌入、固定画像聚合、批量判定和确定性缓存。拟探索的贡献在于它们围绕同一专家来源、要求范围及预算的组合。本文不将低维候选筛选、AND 门控、反事实修改或关闭模型推理单独宣称为原创算法；当前实验证据也不足以证明三项研究问题均已解决。

## 2. 相关工作与研究边界

专家检索需要将文档或成果证据聚合到个人。现有语义画像、概念索引和分层检索与我们的多分辨率设计具有直接重叠；原有近邻审查保留在 `docs/exploration/closest-work-review.md`。检索树导航、图检索和预算控制为减少在线工作提供了组件，但不能仅凭系统采用这些组件就认定形成新的方法贡献。

画像模型与文档边缘化早已有成熟的概率建模基础，见 [Balog 等](https://doi.org/10.1145/1148170.1148181)。标注预算下的无偏系统比较见 [Schnabel 等](https://www.microsoft.com/en-us/research/publication/unbiased-comparative-evaluation-ranking-functions/)，不能把优先判断重要单元或处理缺失标签本身视为新思想。曝光公平性与流行度校正也已有独立研究，分别见 [Diaz 等](https://www.microsoft.com/en-us/research/publication/evaluating-stochastic-rankings-with-expected-exposure/)和 [Boratto 等](https://arxiv.org/abs/2006.04275)；我们目前的关联增益不宣称替代这些指标。

约束评价也已有明确前作。[FollowIR](https://arxiv.org/abs/2403.15246) 通过成对修改指令及 p-MRR 测量排序响应；[ComLQ](https://arxiv.org/abs/2511.12004) 使用逻辑结构引导查询合成并评价否定约束；[n-Clue](https://arxiv.org/abs/2607.24165) 区分完整条件证据与部分匹配的排序。我们需要在这些评价之外检验专家场景的来源归属、独立主题与联合应用关系，以及资料未知的语义，而不是重命名已有覆盖指标。

来源保真也已有系统评价。[ALCE](https://arxiv.org/abs/2305.14627)（EMNLP 2023）分别评价回答正确性与引用质量；[FaithEval](https://arxiv.org/abs/2410.03727)（ICLR 2025）已构造不可回答、冲突与反事实上下文。因此，提供原文引文、删除上下文或报告 unknown 本身不能作为新贡献。专家场景还需要验证归属、真实需求相关性与条件间关系，并避免把对既往事实的审核误当潜在技术匹配标签。当前模型复审尚未达到这些前作的人类验证标准。

## 3. 方法

### 3.0 任务定义：证据支持的需求解决能力推断

输入是完整企业需求及专家论文、简介等归属资料；输出为专家排序，以及逐要求的事实证据、适用性理由、迁移假设和未覆盖条件。历史事实蕴含与未来解决能力不是同一变量。未发表过相同应用不等于不能解决需求；有相关关键词也不等于能够解决需求。对于每个要求，区分已有直接应用证据、可解释的方法迁移、仅主题邻近和资料不足。方法迁移必须同时给出原始证据、从已展示方法到目标问题的机制解释及仍待验证的假设。未来性能目标保持为待实现目标，不能写成既有业绩；明确既有资质条款另行核验。

新增 `applicability.py` 定义上述适用性输出与固定序数排序协议：优先比较直接应用与可解释迁移覆盖，再比较直接覆盖与仅主题覆盖；迁移存在时仍保留未决条件。所有非不足判断必须引用同一专家的真实来源跨度，迁移必须有机制与未决假设。该协议需要独立语义评价，覆盖值不是成功概率，也不以引用存在代替蕴含或适用性验证。该模块尚未形成实证有效的新方法，三个行为测试只验证归属、迁移缺口保留及排序规则。

### 3.1 来源保真的多分辨率表示

令专家集合为 E，专家 e 的原始证据集合为 D_e。每项证据保留专家标识、原始记录位置及文本。所有生成式能力描述均为衍生表示，不能替代原始来源。

系统提供三类表示：原始成果及字段、冻结向量、来源化能力卡。能力卡必须能够回溯到同一专家的连续原文；引用失败时保留失败记录并回退到原始表示，不跨专家拼接能力。词法索引预计算倒排分数并按需读取最终命中文本，以降低工程开销。这项预计算是工程基线优化，不是论文核心创新。

对于成果向量，基线分别使用最大成果相似度和平均画像相似度。固定混合使用两者各 0.5 的权重，没有利用测试标签调参。低维候选阶段使用已有嵌入的前 256 维筛选 100 个文档，再使用完整 1,536 维向量重排。该近似筛选不保证候选集之外的全局精确性；查询编码、索引加载与本地计算分别计时。

### 3.2 原子要求与关系要求

将查询表示为要求图 Q=(V,R)。V 表示研究主题或能力要求，R 表示显式的联合应用等关系。只有查询实际要求关系时才创建关系条件；不得把普通的主题并列解读为联合应用、独立领导或独著要求。

对于每个要求，外部判定结果取 supported、contradicted 或 unknown。unknown 表示当前资料不足，不等同于实际能力为负。关系必须获得自身的支持判断；即使所有端点都获支持，也不能自动推出关系获支持。若关系端点尚未获支持，则不能把该关系计为完整已证实条件。代码同时检查依赖引用和环路，避免无效要求图产生得分。

协议还必须区分未来项目目标与候选人的既往事实。例如，项目希望达到某个识别率，不等于候选人过去必须已发表达到该数值的成果。联合应用关系未知，只限制对其既往联合经验的断言，不能自动把潜在研究相关性置零。只有明确要求的候选资质或既往事实才适合作硬门控。相关性排序与推荐语句的证据完整性分开评价；目前通用解析器尚不能可靠完成这种角色区分。

当前实现已经具备范围评分原型，尚未完成可靠的通用自然语言要求图解析器。解析器遗漏必要条件会直接损害后续评分有效性，因此不得通过默默截去多余条件维持固定预算；当前约束代理对超限计划明确报错。

### 3.3 在线核验与返回时序

在线流程先给出可用的检索结果，再在预算允许时读取来源、核验要求或生成解释。结构化结果、完成核验的结果和长解释分别记录到达时间，不能用首个粗排序的速度代替完整回答速度。

固定内容缓存的键包含判定模型、提示版本、完整要求与证据文本。缓存加速仅适用于相同内容复用，不计为未知新查询的速度收益。现有有界聚合原型的证书只针对固定候选集及固定评价器分数，不能证明语义正确性或全语料完整性。

Decisions API 提供了适合批量固定选项判定的后端。项目已实现原生适配与响应校验，但当前网关即使使用兼容文本输入，仍返回 unsupported operation。因此本文没有 Decisions 精度或提速实测结果。已有核验使用普通结构化输出，不能将其标为 Decisions。

### 3.4 向量化分数区间与精确前 K 重放

对于已编译的非负加性语言模型，逐项 Python 累加可由向量化区间计算替换。每次加法分别向负无穷和正无穷取相邻浮点数，得到包含参考精确累加结果的下界 L_e 与上界 U_e；乘法保留与参考实现相同的 float64 舍入。取按分数及专家 ID 排序的第 K 个下界作为阈值，只对上界仍可能超过该阈值的候选使用 math.fsum 重算，再按原有规则排序。分数相等时使用专家 ID，零分查询也保留同一顺序。

该过程保证的是固定模型的有序前 K 及返回分数，不是语义正确性。区间阶段仍访问所有活跃倒排项，也维护与语料规模相同的上下界数组；精算候选减少不能解释为倒排读取或神经调用同比减少。这是两阶段安全评分的工程实现；Broder 等人的 WAND（CIKM 2003）已研究近似候选与完整评分，本文不声称首创该总体范式，也没有把此处区间实现称为 WAND。

## 4. 数据构造

### 4.1 原始数据与完整需求层

本地教师语料包含 10,673 位教师、54,409 篇关联论文及 42,340 条画像字段证据。企业需求表包含 4,301 条记录。当前需求试验使用固定随机抽取的二十条需求，规模不足以代表全部产业分布。

完整需求层保留原文、字符偏移及来源。条款抽取排除标题与显式背景，并验证连续原文、唯一位置和不重叠。此类结构验证不能代替对未标记段落的语义审核。

五条需求提取出十条技术条款，每条检索两位教师，共二十个组合。将同一教师的证据从一条增加至最多三条后，双模型仍均判 unknown。这不证明不存在匹配专家，只说明当前候选及有限证据不足以支持完整要求。

### 4.2 范围控制的窄化能力任务

生成器依据单一专家的原始证据选择二至三项研究主题，并保留与原需求共享的具体技术主题和原需求尚未覆盖项。代码用统一模板表达各主题分别考察、不要求联合应用，避免自由生成额外加入工业部署或性能要求。

反事实由索引和替换主题确定，代码只替换一项要求。生成器不能预设缺失能力就等于实际不具备能力。独立模型审核完整查询、全部修饰项、反事实支持状态、单项变化及与原需求的主题关联。审核过程保留失败与分歧；生成与审核的最终 schema 一致。

四十个候选中十四对通过审核，覆盖十一条需求、十三位教师；二十个被语义审核拒绝，六个未通过结构验证。通过的二十八个查询变体是小规模 silver 诊断数据，标签只约束构造专家和所给来源快照，其他专家仍未判定。相同需求、专家或来源必须在未来切分中保持连通分组，不能把配对变体当独立样本扩大统计显著性。

### 4.3 联合关系诊断

在十四个原子主题获支持的样本上，追加“同一项研究将全部主题联合应用于一套技术方案”的要求。十二例获得双模型 unknown 判断，两例存在分歧。分歧不转换为确定标签或确定关系得分。此诊断说明关系应单独审核，但没有人工金标，尚不能证明评分协议的用户效度。

另外保留五百条精确研究方向合取任务及四十九条通过模型等价审核的语义改写。它们用于索引和来源恢复诊断，不能替代产业需求数据，也不能将未标注专家当作语义不相关。

## 5. 评价协议

常规检索使用 nDCG、MRR 与 Recall；CMU Gold 使用保留分数差权重的成对排序损失，缺失标注不作为负例。失败的模型输出在正式对照中按同分处理，不能只报告成功子集。

约束评价分别报告原子覆盖、关系覆盖、必要条件满足状态和未知权重。加权覆盖仅作为局部证据支持量；必要条件缺失时，完整适配得分受到门控。该设计与已有完整覆盖评价有继承关系，尚不宣称新的指标理论。

时间评价使用截止时刻之前最新一次完整结果快照的得分，而不是历史最优快照，以显露后续排序退化。分别报告冷启动、在线编码、检索、核验、解释与缓存命中条件。无输出的截止时刻计零。后续仍需检验该协议与实际用户决策的关系。

## 6. 实验结果

### 6.1 文档检索效率

| SciFact，300 查询 | nDCG@10 | Recall@10 | 延迟口径 |
|---|---:|---:|---|
| BM25 | 0.6605 | 0.7876 | 本地检索 p50 19.22ms |
| API 冻结向量，完整检索 | 0.7261 | 0.8549 | 缓存查询向量下，本地检索均值 0.751ms |
| 同向量低维筛选及完整精排 | 0.7261 | 0.8549 | 同一配对本地计时均值 0.318ms |
| 本地 BGE-small-en | 0.7201 | 0.8452 | 在线本地编码加检索 p50 5.40ms |
| 本地 BGE 与 BM25 固定 RRF | 0.7127 | 0.8346 | 编码、检索及融合 p50 26.41ms |

低维筛选仅在该数据集上保持相同汇总指标，不表示每条排序相同或普遍无损。API 在线编码五次试测约为 0.52–1.40 秒，远高于本地检索，不能把 0.318ms 写作该 API 系统的端到端耗时。固定融合未改善质量或速度，保留为负结果。

### 6.2 专家相关性排序

| 词法最大成果 | 0.2784 |
| 冻结向量最大成果 | 0.2545 |

能力卡未优于固定原始表示混合。none 与未指定档位的平均模型调用耗时分别为 2.05 秒和 13.13 秒，但两组不在同一时段交替执行。none 减固定混合的损失差为 −0.03223，研究者级 bootstrap 95% 区间为 [−0.08730,0.02044]，不能宣称显著精度优势。

额外固定随机抽取六位研究者，进行两轮平衡交替 none/medium 对照，共二十四次调用。平均调用耗时为 1.94 秒和 13.74 秒；两轮加权损失均值为 0.09783 和 0.14452。研究者宏平均差的 95% 区间为 [−0.09090,0.04840]，同样不支持精度优势或质量等价。该子集不可与全五十八位结果直接作绝对高低比较。

### 6.3 公开约束任务与复算

n-Clue 官方冻结榜单已在固定提交上通过全部声明及校验和复算，覆盖 v1 七十个系统及 v2 三十九个榜单。这是评价方法的独立复算，不是我们的检索系统成绩。

ComLQ 已按官方固定提交及归档 SHA-256 接入通用接口，保留逻辑类型并排除答案字段进入查询输入。在 11,251 篇文档、2,909 条查询上，BM25 的 nDCG@10 为 0.6663、Recall@10 为 0.8865、检索 p50 为 53.09ms；TF-IDF 分别为 0.6653、0.8801 和 52.30ms。本地 BGE-small-en 为 0.4736、0.7681，在线编码加检索 p50 为 6.10ms。这体现质量与速度的取舍，没有方法同时占优。nDCG 使用 TREC/BEIR 的线性等级增益；词法分词与原论文实现可能不同，不能称作逐值复现其 BM25。这里没有从普通 qrels 推导否定违反标签，也没有填报 LSNC。上述两项均为文档检索，不能代替产业专家相关性。

固定种子抽取一百条合取查询进行额外探索，规划器只接收原查询，不接收答案、类型或 qrels；五十二条被判为可安全分解，其他查询回退并保留在分母中。整句向量、条件向量均值、条件最小值、固定条件融合及 BM25 的 nDCG@10 分别为 0.6080、0.6278、0.5530、0.7197 和 0.8240。条件分解未优于强词法基线，且规划调用均值为 1.78 秒，尚无效率优势。部分问题的证据分布在不同文档中，要求每篇文档满足全部条件与任务单位不一致；专家任务则应先在同一人内部聚合来源。上述试验不能作为方法创新成功的证据，也不能把多方法一起运行的时间冒充单个方法延迟。

### 6.4 直接专家匹配数据的补充验证

为减轻作者恢复与文档检索代理任务的局限，接入 [CoF 官方发布](https://github.com/yuz9yuz/CoF)的 SIGIR、NIPS、SciRepEval 和 KDD 数据。SIGIR 的七十三个查询均覆盖一百八十九位候选，标签由人工标注的研究主题 Jaccard 相似度离散映射得到，而非独立人工判断全部 13,797 对匹配。其他三套数据只在每个查询的已判定候选集合中评价，不能把其余人当作负例。具体数据审计见 `docs/exploration/cof-datasets.md`。

SIGIR 上，BM25 最大成果的 Soft P@5/P@10 为 0.3973/0.3822，Hard P@5/P@10 为 0.1973/0.1712；前三成果聚合分别为 0.3781/0.3712 和 0.2000/0.1808。冻结向量最大成果、平均画像和此前固定的 0.5/0.5 混合画像的 Soft P@5/P@10 分别为 0.3890/0.4041、0.4000/0.4082 和 0.3808/0.4110；Hard 分别为 0.1753/0.1808、0.1589/0.1603 和 0.1644/0.1740。此前在 CMU 有利的固定混合没有稳定迁移到 SIGIR，不能将其作为已验证改进。该基准直接排序专家，但仍不等同于产业需求适配。

原始数据审计发现，SciRepEval 的十六条查询及 KDD 的一条查询，其完整题名与摘要以不同编号出现在画像中。因此编号不相交不足以排除直接复制泄漏；后续结果必须区分原协议与查询级文本复制排除对照。当前 SIGIR 未发现此类精确复制，仍不能据此排除近似改写。

### 6.5 模型标注的开放世界错误

在十四个合成查询的多方法候选并集上，对一百五十三个专家组合使用同一词法前三证据加研究领域的来源策略。初次完整查询判定出现了七例双模型共同把其他研究领域当作“矛盾”的情况；这不构成显式否定证据，故整轮输出不作为可靠评价使用。跨模型一致本身不能保证正确。

随后改为逐主题的 supported/unknown 判定，并验证每项支持引用。三百二十六个原子组合中，六十个双方同判支持、一百七十六个同判未知、九十个未决；完整专家组合为十一个支持、八十五个未知、五十七个未决。部分未决来自输出 ID 或引用校验失败，不是语义负例。来源截断、共同词法选证及模型偏差仍存在，当前不足以作为金标或方法优越性的依据。

### 6.6 同候选池的证据预算实验

SIGIR 的七十三条查询使用同一个固定混合画像召回的二十人候选池，随机匿名编号；比较完整成果、按相似度截取、按查询词边际覆盖截取三个条件。后两者每人预算 2,400 字符，最多每篇取一段，保持原文偏移及归属。模型、提示、候选及标签一致，均为 gpt-6-luna、reasoning_effort=none；失败保留粗排回退，不剔除查询。

| 证据条件 | Soft P@5 | Hard P@5 | 平均输入 token | 调用均值/中位数/P95（秒） | 失败 |
|---|---:|---:|---:|---:|---:|
| 完整成果 | 0.4055 | 0.1726 | 54,652 | 4.516 / 3.773 / 5.404 | 0 |
| 相似度截取 | 0.4192 | 0.1890 | 9,614 | 8.845 / 2.901 / 34.445 | 1 |
| 边际覆盖截取 | 0.4110 | 0.1562 | 9,649 | 4.026 / 2.701 / 4.333 | 3 |

相似度截取相对完整成果的 Soft P@5 配对差为 +0.0137，查询 bootstrap 的探索性 95% 百分位区间为 [-0.0247, 0.0548]；Hard 差为 +0.0164，区间 [-0.0110, 0.0438]。不能据此断言优越或非劣。覆盖截取相对相似度截取的 Hard P@5 差为 -0.0329，区间 [-0.0575, -0.0109]，显示按词覆盖预算可能损失细粒度匹配。上述区间假定查询独立，未做多重比较校正，不能作为确认性检验。

该轮采用三个循环顺序，未平衡前序请求；相似度条件存在显著延迟尾部，不能把 token 降幅直接换算为在线加速。网关小请求返回的 token 限额为每分钟 250,000，但这不能证明尾部的具体原因。共享格式对照采用六种顺序、逐次 HTTP 状态与限流响应头记录，并单列保守限流等待；七十三条查询的三条件均已完成。完整上下文也做逐字相同来源文本复用，避免仅给压缩条件去重。文本复用保留每个候选原有来源边，不把相同文本推断为独立世界事实。

共享格式全量结果中，完整/相似度/覆盖的 Soft P@5 为 0.3699/0.4137/0.3644，Hard P@5 为 0.1836/0.1863/0.1671。输入平均 token 为 48,527/8,263/8,776；模型调用均值为 4.166/2.377/2.428 秒，P95 为 6.753/3.203/3.552 秒。相似度截取减少约 83% 输入 token、调用均值缩短约 43%，但相对完整的 Soft P@5 差 0.0438 的探索性区间为 [-0.0082,0.0986]，Hard 差 0.0027 的区间为 [-0.0384,0.0466]，精度优势及非劣性均未确立。所有 HTTP 尝试为 200，完整条件一次输出排列无效，已计入回退。保守限流等待均值分别为 9.934/0.111/0.289 秒，另行报告；它属于测量调度，不能从用户端到端时间中隐去后再宣称同等在线加速。该轮与原格式结果的差异也提示单次模型运行不稳定，尚需独立重复。

NIPS 的三十四条查询采用原发布的已判定候选集合（每条 1–17 人），共享格式全量三条件也已完成。完整/相似度/覆盖的 Soft P@5 为 0.5588/0.5176/0.5412，Hard P@5 为 0.2824/0.2765/0.2706；调用均值为 4.576/2.201/2.126 秒，平均输入 token 为 76,995/7,246/7,626。相似度截取的 Soft 差 -0.0412，探索性区间 [-0.1000,0.0176]，再次不能声称无精度损失。覆盖条件一次输出无效并保留粗排回退。单候选查询一条，排名无需模型决策；后续服务对所有方法都应共同跳过该情形，不能把省去此类调用当作新方法收益。P@5 的候选池内 oracle 上限为 Soft 0.7118、Hard 0.3647，不能假定小候选池也有 1.0 的绝对精度上限。

### 6.7 查询关联增益与静态画像先验

SIGIR 的静态“小画像优先”列表取得 Soft P@5=0.4740，高于目前若干查询驱动方法；这说明绝对相关性和查询关联性应分别测量，而非证明标签无效。通用专家可能在许多需求上都具有实际价值，静态先验也应作为强对照保留。

令 a(q,e) 为查询 q 对专家 e 的归一化前 K 位曝光权重，y(q,e) 为相关性，ā(e) 为跨查询平均曝光，ȳ(e) 为跨查询平均相关性。定义固定查询集的关联增益 L=(1/Q)Σq,e a(q,e)[y(q,e)−ȳ(e)]，等价于实际加权收益减去均匀打乱查询与排序对应关系后的期望收益。静态列表的 L 恒为零。该量补充绝对 P@K，不应单独优化；其属于机会校正思路的任务化原型，尚未证明文献新颖性或用户效用。

对缺失标签保持 y∈[0,1]，写 c(q,e)=[a(q,e)−ā(e)]/Q。已知项求和后，对未知项分别加入 min(c,0) 与 max(c,0)，得到固定数据上的精确识别上下界；这不是置信区间。比较两方法时先相减系数再求界，保留共享未知标签的约束，避免独立求界导致无谓放宽。

SIGIR Soft P@5 的 BM25-max、向量最大成果、固定混合、密集邻域富集及静态小画像先验的关联增益分别为 0.0260、0.0044、0.0002、0.0407 和 0。富集分数采用固定深度邻域的超几何尾概率校正画像长度，无训练，但 Soft P@5=0.4192，仍未超过静态先验。原始邻域票数的关联增益更高而绝对 P@5 更低，也表明该量不可替代绝对质量。当前不据此宣布新指标贡献成立。

### 6.8 查询拆分及字面数据挖掘的失败对照

冻结 BGE-small-en-v1.5 对 SIGIR 的完整查询表示和题名加摘要句段分别编码，所有来源统一为原文前 1,200 字符，逐字相同窗口复用并保留归属。实际源数据已小写化，初版只识别大写句首导致每条查询只有题名与整段摘要两个单元；该版仅作调试记录。修正后平均 7.82 个单元，整句最大成果、专家内各单元最佳成果再平均、专家内各单元最佳成果再取最小值、单篇内取最小值再跨篇取最大值的 Soft P@5 分别为 0.4329、0.4027、0.3452、0.4137，Hard 分别为 0.1753、0.1726、0.1644、0.1479。拆句和多来源聚合没有稳定收益；原始摘要句子不能直接当作必要条件。该对照是已有 MaxSim/集合聚合思路的实例，不宣称算法原创。

NIPS 上，整句最大成果、专家内句段最佳证据均值、专家内句段最小值和单篇最小值的 Soft P@5 为 0.5294、0.5529、0.5000、0.5000，Hard 为 0.2471、0.2706、0.2412、0.2353。均值聚合在这套数据较好，但仍未超过经典候选语言模型，不能从 SIGIR 或 NIPS 中挑选各自最有利的聚合后宣称统一方法。

另一条直接从真实需求与中文论文题名挖掘公共子串的路线得到十八组候选，但每组至少含有功能词碎片或非技术短语。加入基础短语筛选后，同一二十需求上的合格族为零，未纳入数据发布。标准二分图匹配可检查不同来源绑定，但匹配器正确不代表生成的任务有语义质量，不能以结构证书替代术语和需求关联审核。

### 6.9 经典专家语言模型及精确索引编译

补充 [Balog 等（SIGIR 2006）](https://doi.org/10.1145/1148170.1148181) 的候选语言模型和文档边缘化语言模型，固定背景插值 λ=0.5，不以当前标签选参数。候选模型先平均每篇文档归一化后的词分布，再平滑并计算查询似然；它不同于把画像所有词频直接相加。文档模型则对整条查询的文档似然按来源关联边缘化。二者均为经典方法，不作为本文原创排序公式。

候选模型的查询分数在去掉查询常数后为 Σt n(t,q) log[1+(1−λ)p(t|e)/(λp(t|C))]。固定语料与 λ 后，可预编译每个非零词—专家贡献；查询只访问倒排项并用 math.fsum 汇总。三次随机交替顺序、全部 107 条查询的分数与原始实现完全一致，编译并未改变精度。数组负载为 SIGIR 1.01MB、NIPS 3.30MB，不含 Python 对象、原始语言模型和文本的内存。

| 数据 | 方法 | Soft P@5 | Hard P@5 | 本地查询均值 |
|---|---|---:|---:|---:|
| SIGIR | 优化 BM25-max | 0.3973 | 0.1973 | 27.53ms |
| SIGIR | 候选语言模型原始/编译 | 0.3836 | 0.1753 | 3.859 / 1.089ms |
| NIPS | 优化 BM25-max | 0.5118 | 0.2647 | 169.82ms |
| NIPS | 候选语言模型原始/编译 | 0.6000 | 0.2706 | 7.783 / 1.878ms |

以上运行对全部可用画像评分并排序，NIPS 的质量随后仅在原协议已判定候选内评价，不外推为全库相关性。计时包含分词、评分和排序，离线构建另计；重复时序已有随机化，但机器同时存在网络实验，不是隔离硬件测试。NIPS 上经典方法同时优于 BM25 的精度和本地时间，SIGIR 则未保持精度优势，不能宣称普遍领先。预编译是经典加性公式的工程优化，应成为后续组合方法的强基线。

NIPS 的经典候选模型相对 BM25-max 的 Soft P@5 配对差为 +0.0882，探索性查询 bootstrap 区间 [0.0294,0.1471]；收益来自已有评分模型，不来自编译。SIGIR 未保持同方向增益，仍须更多任务及强语义重排对照。

完整本地教师语料上，96,749 条证据涉及 9,861 位有可用证据教师；另外 812 位教师没有可用索引证据，不能将其视作不具备能力。使用二十条原始企业需求，三次逐查询随机交替顺序，预编译并从磁盘重新加载后的分数及完整排序均与参考实现完全一致。本地查询均值从 720.31ms 降到 42.43ms，中位数从 622.31ms 降到 25.13ms；不含离线构建与加载。参考统计构建约 38.42 秒、贡献编译 6.46 秒、保存 3.71 秒、索引加载 1.87 秒；数组负载约 66.04MB、磁盘文件约 55.08MB，均不等于进程总内存。真实需求尚无独立相关性金标，因此该实验只证明执行等价与局部计算收益，不能证明其产业精度。持久化检索入口还报告冷初始化与查询分别耗时，见 `compiled_expert_search.py`。

查询关联增益还存在额外标注负担：比较邻域富集与 BM25-max 时，P@5 差只涉及 584 个非零系数单元，关联增益差却涉及 10,033 个。等成本且能取得确定数值标签时，优先标注绝对系数较大的单元能最大限度缩小线性区间宽度；这是标准系数质量调度，不是新的无偏抽样理论。回放隐藏标签的实验验证了区间始终包含完整标签结果，但代价仍很高。例如标注 1,000 个单元后，该关联差的最坏情形区间宽度仍约 0.796。未知或有歧义的真实标注不能被当成已解决的数值标签；此结果限制了该指标在稀疏产业数据上的可用性。

### 6.10 合成候选扩展与完整条件对应

同一二十条真实需求以题名进行冻结 BGE 中文研究领域检索，每条选两位新候选；统一补充词法前三证据和可用的中英研究领域原文，再沿用 scope-v5 生成和审核。四十次构造产生二十三对初审 silver 候选，旧词法批次为十四对；在同一需求内，新批次候选与旧词法前二候选没有重合；这不是跨需求的全局专家去重统计。本轮同时改变候选检索与来源策略，不能把接受率差异单独归因于语义检索。两批仍共享需求，不构成独立测试集。

原审核要求“至少两条引用”，可能未机械保证三条件查询逐项覆盖。新增逐条件复审使用固定条件 ID，两个模型都必须逐项给出完整条件支持、唯一原文引用，以及反事实替换条件的 unknown；需求关联也必须给出原需求中的唯一精确引用。模型不接收生成器的预期标签、引用或理由。导出时重验源产物哈希、完整模型集合和原始输出，避免文件变化后套用旧判定。两批三十七对初审候选的复审已完成：十四对通过、十三对被复审否决、十对未决。通过集覆盖十条需求和十四位教师；按共享需求、专家、所有输入及引用的来源快照哈希和重复查询传递连接后形成十个分量，切分为八/三/三对。导出还保存全部输入来源的哈希和前缀长度，加载器重建原审核上下文，不能只给被引用的正向片段。该流程仍使用相同两个模型家族，不是独立人工金标，精确定位也不等于语义蕴涵保证。

该审阅集的测试切分只有三对；给定条件结构的字面匹配基线已取得 1.0 的状态准确率，全部十四对为 0.9286。它可以检查来源重建与 unknown 处理，但区分度不足以证明复杂推理方法的必要性。下一步应检验同一专家、同一原子主题下的关系证据变化，而非仅增加同模板改写。详细字段与限制见 `docs/scoped-dataset-card.md`。

### 6.11 冻结交叉编码器与离线语义传输

补充 FlashRank 0.2.10 的 TinyBERT-L2 和 MiniLM-L12 对照，无任务训练，ONNX CPU 单线程、最大联合长度512。沿用 Luna 相似度条件的候选池与原始来源窗口，比较串接后单次评分及逐来源评分取最大值；相同来源输入不等于相同有效 token 暴露。完整数值见 `docs/exploration/crossencoder-results.json`。TinyBERT 逐来源最大值在 SIGIR/NIPS 的 Soft P@5 为 .4000/.5000，Hard 为 .1973/.2471，推理均值 .137/.173秒。MiniLM 相应 Soft 为 .3753/.5000，Hard 为 .1699/.2412，均值3.642/5.244秒。计时不含召回与来源准备，单次运行，不支持端到端速度结论。固定等权融合未取得一致收益，未继续为该融合构造剪枝算法。

离线语义传输原型采用冻结 BGE 词向量的互近邻核，同时变换专家分布与背景分布，之后预编译；固定 k=8、自环质量 .5、JM=.5，没有按查询标签调参。SIGIR Soft P@5 从经典 Model1 的 .3836 到 .4082，Hard 从 .1753 降为 .1671；NIPS 两项 P@5 均保持 .6000/.2706。预编译与直接参考分数全部相等，单次暖查询均值 SIGIR 1.338ms、NIPS 2.224ms，另计离线向量与核构建。结果支持进一步检查语义平滑的指标权衡，尚未证明综合精度提升。统计翻译检索属于已有路线，不能把该核或编译等价性单独宣称为新理论。

来源关系反事实六例试验中只有三例完成结构构造。修复审核提示把三个 ID 写成一个字面字符串的错误后，对这三例重新进行双模型、双上下文审核，结果两例否决、一例未决，无通过。保留原始试验和修正复审，不能将原先格式错误解释为语义证据。后续需改进真实需求关联的来源选择，不能降低标签标准凑数量。

同六例改用本地多语言编码器按需求题名挑选四篇来源后，生成可行性试验为2例构造成功、4例结构拒绝；尚未独立审核，不新增有效标签。一例为249字符超过240字符上限，而原提示未显式声明此上限，这属于协议格式问题；另两例独立见证被别名闭包删除、一例引文失败。当前网关的embedding和GPT-6-Luna探测均返回400，因此明确区分来源准备、生成可行性与完整双模型审核，不将后端不可用算作数据语义否决。

### 6.12 完整教师库的有序前五名执行优化

在同一持久化快照的9,861位有可用证据教师上，对20条完整原始需求进行每条5次随机方法顺序的配对计时。对照为原编译模型全量评分加堆选前五名，新方法为区间计算与精确重放；双方都包含选择开销。最新 v2 运行的均值14.429→6.427ms，中位数13.907→5.953ms，均值比约2.25。全部100次比较的前五位、顺序及浮点分数完全一致；每次仅五位需要精确重放。冷初始化1.521秒，另计。此结果只支持该暖执行路径的速度提升，没有真实需求相关性标签，不能宣称质量提升，也不能直接与此前全排序计时相除。常规短查询CLI也已实际执行。

对语义传输另外逐查询重算标签指标，SIGIR Soft P@5 差的探索性配对95%区间为[-.0055,.0548]；NIPS为[-.0235,.0235]。NIPS有29/34条查询前五位顺序改变，即便平均P@5相等也不表示排序等价。Hard nDCG@10 差点估计为-.0205，区间[-.0536,.0074]。因此尚不把该语义核固定为默认质量改进。

### 6.13 冻结Qwen3补充对照

官方Qwen3-Reranker-0.6B固定版本e61197ed45024b0ed8a2d74b80b4d909f1255473的权重与分词文件已按官方LFS哈希核验。MLX使用BF16骨干及FP32的yes/no输出行，在同一相似度来源窗口上评分，最大4096token、批量4。短输入的两行投影与全词表参考概率最大误差约7.5e-9，右侧补齐批量与串行的最大差约1.3e-11。

NIPS全部34查询、393候选的Soft/Hard P@5为.5647/.2824，未发生截断。相对同候选池Model1的P@5差分别为-.0353/+.0118，探索性配对95%区间分别为[-.0824,.0118]/[-.0235,.0471]。当前结果尚未证明一致优势。初始运行均值7.106秒，包含分词、GPU推理与排序。SIGIR初始运行出现系统内存压力并中断，随后采用4GiB分配和128MiB缓存上限重新运行，完整结果待核算。

SIGIR有内存上限的Qwen运行现已完成73条查询、1460候选，Soft/Hard P@5=.4301/.1890，均值4.010秒，无截断。对同一候选池Model1的Soft nDCG@10差为+.0262，探索性95%区间[.0018,.0503]，两项P@5差区间均跨零。后验固定等权融合在NIPS的Soft/Hard P@5=.5941/.2882，在SIGIR为.4000/.1808，跨数据集收益仍不一致。融合实验使用已观察过的基准，结果支持继续探索而尚未提供留出验证。


固定融合的按需评分回放进一步检查效率空间。利用慢分数范围[0,1]及快速先验构造候选上界，并处理ID平分规则，107条查询的有序前五名与完整融合一致。NIPS/SIGIR仍分别需要342/393和1219/1460次候选评分，候选数节省约13.0%/16.5%。GPU批处理与文本长度的成本尚未进入该回放，实际延迟仍需测量。当前结果尚不足以支持极致搜索效率的主要贡献。



### 6.14 查询前缀KV复用的配对试验

固定取每个公开协议前六条查询，各重复两次并随机安排方法顺序，共24次配对。NIPS完整计算与缓存的平均耗时为2.404/1.885秒，均值比1.275，12次前五名顺序全部相同。SIGIR为3.787/2.790秒，均值比1.357，但只有6/12次前五名顺序相同，Hard P@5平均差为-.0333。两组最大概率偏移分别为.0488/.0289，分段BF16计算改变了数值结果。该实现的速度收益需要结合精度变化评价，当前仍需解决分段前向的数值稳定性，并在完整查询集验证。



相同12条查询的FP32复验共24次配对，NIPS完整/缓存均值3.344/2.670秒，SIGIR为5.145/3.867秒，速度比分别1.252/1.331。两组12次前五名均全部一致，最大概率差约8.52e-6/4.95e-6，所测P@5和nDCG@10保持相同。FP32缓存的绝对耗时仍需与BF16完整计算比较，当前只支持相同FP32精度下的复用收益。



跨精度绝对耗时比较显示，FP32缓存在本试验NIPS/SIGIR上分别较BF16完整前向慢约11.1%/2.1%。该比较来自同一查询集合的两次运行，尚非跨精度随机交错计时。当前证据支持保留前缀复用作为精度与效率权衡组件，进一步主方法需要扩大复用范围。

辅助审核的六份结构合法输出中，两份存在关系支持而端点未知的依赖不一致。普通支持覆盖率分别计为2/3与1/3，已有依赖校正实现将其调整为1/3与0。该实例展示指标能揭示的输出问题，语义标签本身仍需独立核验，尚未建立指标与真实专家匹配质量的关联。

## 7. 局限与待证贡献

当前没有足够证据支持完整系统在精度和端到端延迟上同时优于强基线。来源恢复、合取诊断和独立文档检索不能外推为产业专家匹配质量。现有数据筛选也依赖模型，可能存在过度拒绝、范围误读及共享模型偏差；跨模型一致不等于事实正确。

尚待验证的工作包括：可靠的范围解析、完整索引与预算化核验的统一线上实验、对照 FollowIR/ComLQ/n-Clue 的指标增量价值、更大规模且经质量审计的产业数据，以及在相同后端和时间边界下的强基线消融。负结果表明，增加能力卡、固定融合或增加少量证据并不必然改善系统。

### Decisions API 批处理补充实验（2026-11-16）

当前网关已恢复原生 `gpt-6-luna` Decisions 调用。对冻结的 8 份真实来源盲审视图，每份分别判断两个原子条件和一个关系条件；以固定种子随机安排逐项与三项合批的调用先后，所有 32 次请求成功。逐项顺序调用累计 17.379 秒，三项合批累计 10.112 秒，观察到 1.72 倍延迟改善。两种请求方式的 24 项标签中有 21 项相同。这说明批处理可减少网络调用，但当前输入组织下判断并非完全不变，不能视为无损替换。该试验每份仅一次重复，无人工金标准，尚不能推出准确率或稳定加速结论。复现脚本为 `experiments/decisions_batch_comparison.py`；原始结果保存在 `artifacts/decisions-batch-comparison-v1/`。

后续检查发现，每项 question 的 instructions 原先仅通过记录 ID 指向约束。提示词 v2 在每个 question 中明确重复完整约束，并禁止使用其他记录或其他问题作证据，保持输入证据不变。在同样 8 份视图上重新执行固定顺序随机化试验，逐项累计 16.468 秒、合批 7.574 秒，比值 2.17；标签一致数为 23/24。结果与“绑定更明确可能降低批间干扰”的解释相容，但仅一次重复且存在随机性，不能建立该解释的因果结论。v1 原始结果保留；v2 实验记录后端源码摘要，避免修改提示词后复用旧响应。后端 4 项传输与响应验证测试通过。剩余 1 项差异仍需重复试验与人工证据核查。

### Decisions 直接支持概率排序

新增 `experiments/cof_decisions_support.py`，在 NIPS 全部 34 条查询上复用冻结的 similarity 证据窗口与匿名候选池，验证来源归属及字符偏移后，每个候选设置一个“直接研究专长”完整约束，以 Decisions 返回的 supported 概率降序排序，同分按专家 ID 排序。全部请求成功，Soft P@5 为 0.547059、Hard P@5 为 0.282353，平均请求 2.350 秒（不含上游检索与证据准备）。同池 Qwen3 的对应值为 0.564706/0.282353，Model1 的 Soft P@5 为 0.600000。因此当前将未校准支持概率直接用作排序分数尚未取得质量优势；应继续探索其在条件核验与受约束决策中的用途。此实验有公开标签，可评价排序；这些标签仍不能验证模型的证据蕴含判断。

KDD 的完整词法对照亦已完成：174 查询的 BM25-max Soft/Hard P@5 为 0.319540/0.144828，BM25-top3 为 0.329885/0.145977；编译 Model1 为 0.288506/0.137931。该结果表明 Model1 虽快速，但在此数据上排序质量低于词法对照，不能作为已成立的精度优势贡献。SQLite 词法实现的中位耗时 2.636 秒只代表该实现，不能代表所有优化 BM25 系统。

### 驻内存 BM25 工程对照

为避免把 SQLite 访问开销误写成算法优势，新增 `ArrayBM25`：保留原始预计算 BM25 浮点贡献和排序后的唯一查询词累加顺序，将倒排表常驻 NumPy 数组。NIPS 全部 34 查询逐文档分数与现有 SQLite 参考字典完全相等；固定每查询随机运行先后、每查询一次，SQLite 累计 5.531 秒，数组实现累计 0.0850 秒，约 65.1 倍。初始化 0.431 秒，数值数组 7.91 MB（不含 Python 字符串及容器开销）。数组实现平均每查询约 2.50 ms，仅含文档评分及分数字典构造，尚未包含作者聚合与排序，不能与其他端到端结果直接相除。此结果是工程优化基线，说明此前基于 SQLite 的较大速度差不足以支持方法创新；后续新方法必须与驻内存 BM25 对照。复现命令：`PYTHONPATH=src python3 experiments/array_bm25_check.py`。

驻内存 BM25 补充作者聚合与排序后，在 NIPS 全部 34 查询上，两种聚合（max/top3）和两种标签任务的前十排名及全部评估指标均与冻结 SQLite 基线完全一致，平均 4.734 ms/查询。该计时包含文档评分、全体作者聚合与候选排序，排除加载和初始化；仍为一次重复。实现为 `array_bm25.py`，复现脚本为 `experiments/array_bm25_profiles.py`。

SciRepEval 的完整 107 查询词法对照已完成：BM25-max 的 Soft/Hard P@5 为 0.642991/0.334579，BM25-top3 为 0.644860/0.325234；编译 Model1 为 0.661682/0.349533。Model1 在该数据上均值较高，但 KDD 上相反，提示应检验互补组合与查询条件，而非宣称单一聚合普遍占优。两数据的逐查询配对 bootstrap 与整条精确复制查询排除敏感性结果保存在 `docs/exploration/cof-scale-*-comparison.json`。

### 固定经典排名融合的探索

在观察到 KDD 与 SciRepEval 的方法优劣相反后，固定 Model1 与 BM25-top3 等权 RRF，常数 60，不搜索权重。完整 174/107 查询的融合 Soft P@5 分别为 0.317241/0.663551，Hard P@5 为 0.143678/0.332710。KDD 上低于 BM25-top3；SciRepEval 上 Soft P@5 略高于两者，但 Hard P@5 低于 Model1。故该简单组合尚未实现稳定超越强基线。保留其完整逐查询排名与配对区间作为后续比较，不将事后探索当作独立确认，也不使用缓存排名的时间宣称在线效率。实现：`experiments/cof_rank_fusion.py`。

### 词级最强证据的离线编译探索

进一步固定对每个词在专家全部论文中取最大 BM25 贡献，再对查询唯一词求和。该词级 late interaction 可离线压缩成专家倒排表，无需在线文档聚合。NIPS/KDD/SciRepEval 全量查询平均评分及候选排序耗时分别约 0.296/0.507/0.380 ms（不含初始化，每查询一次）；Soft P@5 分别为 0.494118/0.309195/0.601869，Hard P@5 为 0.200000/0.139080/0.282243。其速度很高，但整体精度不足，尤其 SciRepEval 与 NIPS，暂不作为主排序方法。一个可能原因是各词最强命中来自不同论文，损失共同语境；目前尚未通过分层误差审查验证该解释。保留实现与全量结果，供后续检验候选召回或带共同来源约束的聚合使用，不把速度单项收益写成目标已实现。实现：`max_term_profiles.py`，实验：`experiments/cof_max_term.py`。

### 接口恢复后的四个关系控制候选复审

扩展 `witness_control_auxiliary_audit.py --model` 后，分别以 GPT-4o、GPT-6-Luna 对此前两种构造路线留下的全部四个结构有效候选重做盲视图审查，每模型八份视图。保留原始响应并执行原有唯一原文引文与需求锚点验证；两模型各有六份输出通过格式及引文校验、两份未解决。两者均无候选满足完整/控制视图的预期标签且与需求相关，新增可接纳数据仍为零。通过校验的视图均返回 demand_related=false；两个候选的控制视图仍判关系 supported，提示原关系过宽或仍有语义替代来源。格式失败与语义不满足分别保留，不把未解决等同错误答案。结果表明问题包含需求对齐与关系定义，不能仅通过删除标题相同的论文解决。此为同模型家族辅助审查，不替代人工标注；模型间一致不能证明判定正确。结果目录分别为 `artifacts/witness-control-audit-gpt-4o-v1` 与 `artifacts/witness-control-audit-gpt-6-luna-v1`。

### 需求先行的条件抽取试验

为减少从教师履历反向生成条件所造成的需求漂移，新增 `experiments/demand_first_facets.py`，先仅向 GPT-6-Luna 提供原始企业需求，将最多四个条件分为研究主题、未来项目目标、明确既有资质，并要求每个条件提供唯一原文锚点。冻结 20 个需求后执行，19 次请求返回 HTTP 400，只有一个请求成功且锚点结构验证通过，包含三个研究主题和一个未来目标。接口层失败不能解释为需求不适合或模型语义错误；当前不据此评价抽取质量，也未生成专家能力标签。保存全部失败类型与成功原始响应，待可用性恢复后按同一输入继续，不能用一个成功需求代替完整队列结论。

需求先行 v2 完成全部 20 个需求：15 个通过条件结构与原文锚点校验，共 38 个研究主题条件、20 个未来项目目标，没有抽取到明确既有资质；其余包含请求超时或引用校验失败，不能视为语义负例。研究主题检索得到 76 个未标注教师候选，覆盖 13 个需求。预先固定每个需求按 job ID 取第一候选，GPT-6-Luna 对 13 个具体条件的证据审查均返回 unknown，全部格式有效，仍无新增可接纳数据。此结果仅为候选构造可行性审查，不是检索准确率估计。证据检索诊断显示 227 个来源中 118 个词法得分为零，17/76 个候选的全部来源得分为零；说明不能仅凭领域相似性与中文条件上的论文词法检索确保有效证据。后续应检验跨语言论文检索并保留与词法来源的匹配对照。脚本：`audit_demand_first_pool.py`；所有候选、失败和审查响应均已保存。

固定上述 13 个需求条件与教师候选，使用冻结 multilingual MiniLM 对这些教师的全部 67 篇非空论文前缀（1200 字符、编码上限 128 token）按条件余弦相似度排序，保持每个候选来源数量相同，向审查模型提供原始完整来源。13 个任务的来源集合均改变，但同样的 GPT-6-Luna 审查仍全部 unknown，未新增数据标签。逐例理由显示至少部分候选在教师层面已明显偏离需求，例如基因表达条件对应交通研究论文，因此仅更换同一教师内部的论文选择不能解决候选召回偏差；此解释来自个案检查，尚未形成全队列人工错误分类。代码：`demand_first_semantic_sources.py`，模型、输入和向量摘要及全部审查响应已保留。零新增不能作为需求无可匹配专家的证明。

### 近期相关工作与下一阶段边界

Petcu 等（EACL 2026，https://aclanthology.org/2026.eacl-long.322/）将子查询和文档选择建模为探索与利用，并使用排名信息及人工相关性反馈估计查询效用。该工作提示按缺失条件分配检索预算，但其反馈条件与当前未标注企业任务不同，不能直接搬用其效果结论。Bao 与 Shi 的 IndexRAG（arXiv:2603.16415v2，2026-09 更新，https://arxiv.org/abs/2603.16415）在索引期构造跨文档桥接事实，以一次检索与一次生成支持多跳问答，无额外训练。此先例说明“推理前移到索引”本身并非新颖性；本场景仍需保留同一专家归属、原始证据跨度及关系独立支持约束，避免跨作者拼接虚构能力。后续组合应围绕这些可检验约束及在线预算收益，而非把一般分解或离线推理作为独创贡献。

### 保留 BM25-top3 排序的词级上界可行性

### 全需求队列中的技术主题锚点候选

为寻找数据构造的可行起点，扫描全部 4301 个真实企业需求，以教师中文研究领域中的 4–24 字母数字短语为候选，要求需求中唯一出现、去除嵌套重叠命中，并至少有两个非重叠主题或一个长度不小于八的主题。得到 3561 个需求—教师主题候选对，覆盖 766 个需求；这些是文字锚点候选而非能力或相关性标签。按冻结的匹配主题总长度排序，取前十个不同需求进行 GPT-6-Luna 需求语境审查，八个响应同时通过唯一原文引文校验且判主题位于实际技术要求中，两个未解决。该队列按重合强度筛选，不能用 8/10 推断总体质量；教师是否完成具体操作及完整工业适配仍未验证。全部原文与模型响应本地保存，代码为 `mine_demand_topic_overlap.py` 和 `audit_topic_overlap.py`。

八个论文条件的第一轮双模型盲审仅一项通过，七项未解决；其中多数为模型转述了需求引文，未逐字引用。新增固定跨度选择对照：按原文句界及最长 400 字符、步长 320 的长句窗口生成唯一可定位片段，给每个片段赋 ID，审查模型从 ID 中选择而不生成引文；完整原需求和来源仍提供。首次跨度提示混合了旧引文字段与新 ID 字段，导致格式冲突，结果全部未解决；修正为唯一明确 ID schema 的 v3 后，八项均执行完毕，四项获双模型需求关联与证据支持、三项被拒绝、一项未解决。不同提示与引用接口可能影响语义判断，不能把通过数变化直接称为准确率提升。四项仅为同模型家族银标候选，仍需独立复核所选跨度是否蕴含完整条件；当前未构成工业适配金标准。跨度可重构检查通过，代码为 `audit_paper_backed_spans.py`，所有版本响应保留。

对四个跨度双模型银标候选构造同一教师来源控制：移除两名审查模型引用论文的并集及规范化标题/正文完全相同的副本，从快照外该教师的真实论文中按长度选替代来源，维持来源数量且不少于原文本总长度的 80%。一项无足够替代论文；其余三项分别以独立视图、确定性随机先后调用 Decisions。仅一项呈 full=supported、control=unknown；一项两侧都 supported，另一项两侧都 unknown。后两者不能用于预期的正例—信息不足对。新增的一项仍是单模型控制候选，需独立盲审和引用核验才能接纳；缺失支持不代表教师无法开展研究。代码：`paper_backed_controls.py`，全部来源、协议与结果保留。

三个可构造来源控制对均进行了独立盲视图双模型复审，共六个视图、十二次审查，全部通过 schema 和跨度引用校验。两对获 full=supported/control=unknown 的双模型一致判断；一对两侧均 supported，拒绝作为控制对。原生 Decisions 与跨度引用审查在其中一对完整视图上出现分歧，说明模型接口间一致性仍有限。已将两对四个视图物化为 `paper-controls-silver-v1` 本地诊断数据，保留每个来源全文前缀、SHA256、审查跨度和响应摘要；不划分训练测试、不估计泛化、不视作人工金标。该数据不是完整高质量 benchmark 交付，只是新的构造路线得到的最小银标产物。脚本：`export_paper_controls.py`。

### 固定无训练查询压缩对照

冻结选择原查询中 16 个词，按文档 IDF × (1+log 查询词频) 排序（同分词典序），保留 BM25-top3 聚合。NIPS/KDD/SciRepEval 全部 34/174/107 查询分别随机安排原文与压缩查询先后，每查询一次，包含词选择、文档评分、作者聚合和候选排序。平均耗时从 4.746/41.747/27.511 ms 降至 2.481/15.266/10.328 ms；Soft P@5 从 0.547059/0.329885/0.644860 变为 0.494118/0.328736/0.659813。SciRepEval 出现约 1.50 个百分点的正向点估计，NIPS 明显负向、KDD略低；不能声称普遍精度提升或无损压缩。逐查询配对区间已保存，属于复用数据集上的探索，不作独立确认。压缩所用统计量仅来自论文语料，不使用标签或新词扩展。代码为 `cof_query_compression.py`。

### 冻结 Qwen3 Embedding 强语义基线准备

依据 Qwen 官方模型卡，新增 0.6B 多语言 embedding 基线，使用官方 revision `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`，权重 SHA256 `0437e45c94563b09e13cb7a64478fc406947a93cb34a7e05870fc8dcd48e23fd`，无训练、无自行量化。MLX 加载官方裸 backbone 权重并严格检查参数名称，按官方最后真实 token 池化方式，在 FP32 中归一化，文档不加查询指令。固定 512 token、批量 8；短样本归一化检查通过，批量与逐条编码最大分量差约 0.00205，因此不宣称数值严格等价。SIGIR 全队列的离线向量与查询指令输入分别编码，材料化按块保留输入摘要及耗时；缓存检索耗时必须与在线查询编码区分。模型卡：https://huggingface.co/Qwen/Qwen3-Embedding-0.6B 。该模型本身为外部预训练基线，不能作为本文方法创新。

SIGIR 完整 73 查询、1740 篇履历论文的 Qwen3 Embedding 基线已完成，离线文档及查询编码累计 105.128 秒。max/mean/固定等权 mixture 的 Soft P@5 分别为 0.427397/0.421918/0.430137，Hard P@5 为 0.191781/0.158904/0.172603；max 的 Hard 排序更高、mixture 的 Soft 排序更高，尚未形成统一优势。所有变体一起评分的缓存耗时均值约 1.002 ms/查询，排除在线查询编码，不能与完整 agent 延迟直接相除。相比已有经典与小 BGE 基线，这是应保留的强语义对照；其优势归于外部模型及固定检索配置，尚未证明本文新方法贡献。后续需完整在线计时与相同候选池的配对精度比较。

SIGIR 在线查询实测已完成全部 73 查询：在模型已加载、文档向量预先构建条件下，现场查询编码加专家聚合及三种排序的均值为 95.531 ms，中位数 93.088 ms，P95 119.167 ms；其中查询编码均值 94.117 ms，模型加载初始化约 1.078 秒另计。在线 max/mean/mixture 的 Soft P@5 为 0.427397/0.421918/0.432877。在线有序前五与批量缓存查询分别有 68/59/65 条完全一致，故批量编码的浮点差异确实可改变排名，不能把缓存结果直接作为在线结果。该计时不包含生成解释、约束核查或证据审查，也不是多次重复的稳定性结论。代码为 `cof_qwen_online.py`。

### 需求操作分解与评审一致性诊断

为避免同一研究组件在多个复合需求上重复计入完整覆盖，新增需求独立的操作分解：每个操作保留具名应用对象、单项操作、限定条件及原文片段ID；集成、部署与验证义务单列并链接相关操作。精确同对象、同操作、同限定条件的重复条目、未知依赖及变动原文在结构层拒绝，语义同义重复另审查。仍不把技术组件成立推导成系统义务成立。固定此前九条探索需求，不向规划模型提供教师、能力标签或已知正例，gpt-6-luna生成8条结构有效计划、1条因无效需求锚点未解决，共140个操作和50个系统义务，请求累计106.803秒。该开销不满足极低延迟在线规划目标；分解也仍混入文档交付、通用实现条目及多动作捆绑，不能据条目数量增长宣称高质量数据。

对全部8条有效计划，使用相同提示分别由gpt-4o和gpt-6-luna审查锚定、单一操作性、范围保留、同义重复、遗漏及系统义务。两轮均完成140项：锚定和范围判断各140项一致，单一操作性125项一致，122项同时通过两个模型的三项检查。gpt-4o报1组重复、6项遗漏、4/8计划保留系统义务；gpt-6-luna报0组重复、53项遗漏、0/8保留系统义务。部分gpt-4o“遗漏经济效益分析”与计划中已保留同类义务的内容直接冲突，说明审查也可能忽略义务列表；两版数量差异不能解释为任一版更准确。保留所有分歧及失败，不以一致通过替代正确性，不自动删除争议条目，也不根据模型遗漏建议直接增添企业要求。由于缺乏可信的完整性与语义去重确认，本版计划尚不作为覆盖率分母或评测金标，完整需求能力排序仍待验证。实现及复现脚本为 `operation_plan.py`、`plan_demand_operations.py`、`audit_demand_operations.py`、`compare_operation_reviews.py`，相应工件目录为 `demand-operation-plans-v1`、`demand-operation-audit-v1`、`demand-operation-audit-luna-v1`、`demand-operation-review-comparison-v1`。新增3项测试覆盖操作与系统义务分离、重复及非法依赖、部分计划及变动原文拒绝，全部通过。


### 冻结向量的画像几何分块剪枝对照

为检验粗到细访问能否在不改变专家最大来源相似度的情况下节省检索成本，复用已有成熟Cauchy–Schwarz球上界：每位专家以最多4个实际来源代表分组，按查询点积加组半径上界访问来源。不把球上界称为新理论。固定官方Qwen3 Embedding CUDA缓存，公开CoF SIGIR为73查询、189专家、1740个唯一来源，NIPS为34查询、364专家、14913个唯一来源；参考路径先为每个唯一来源计算一次点积再聚合到全部归属专家，分块路径计入组上界、成员点积与Python分支开销，计时包含完整专家排序，三次交替顺序运行报告每查询中位数的均值，不含编码及agent。

默认BLAS点积下，SIGIR前五顺序72/73一致，NIPS31/34一致；SIGIR最大分数差仅3.33e-16，不能把实数公式相等直接解释为浮点有序列表相等。增加固定逐行求和的einsum对照，完整扫描与分块使用相同点积顺序后，前五顺序分别73/73、34/34一致。该经验一致性仍非形式实数精确性认证，剪枝保留既有1e-12数值余量。稳定点积版本SIGIR跳过18.64%的归属成员，完整扫描0.803ms、分块4.010ms；NIPS跳过2.37%，完整扫描4.903ms、分块15.903ms。默认BLAS版本完整扫描分别0.466/2.306ms，分块3.761/11.565ms，也更慢。构建时间稳定版本为0.021/0.120秒。分块路径还可能对多位作者的共享论文重复计算，故成员访问数不可与唯一来源点积数混为一谈。

此对照不支持将逐专家球分组接入主路径，不再按减少成员次数宣称加速。后续效率方案必须与共享来源向量化及成熟近似索引比较，真正降低访问及调用成本，不能仅把完整扫描改成大量小矩阵调用。代码 `cof_geometric_bounds.py`，四组原始报告在 `cof-geometric-bounds-{sigir,nips}-{v1,stable-v2}`。新增稳定点积分组不变性测试，包含重复来源和不同分组数；相关2项测试通过。


### 成熟HNSW来源索引与专家级回填对照

按Faiss官方索引文档（https://github.com/facebookresearch/faiss/wiki/Faiss-indexes）补充无训练的HNSWFlat内积基线，官方PyPI faiss-cpu 1.16.0，单线程、M=32、efConstruction=128，来源预算预先固定32/128/512、efSearch=max(64,预算)，未依据测试标签选参。来源近邻恢复归属专家，再对入选专家的全部唯一论文重新评分、排序；计时包括近邻、去重、归属回填、完整来源重算及排序。另用IndexFlatIP做相同来源截断与回填，隔离近似图搜索和来源预算截断的影响。向量及查询复用同一官方冻结Qwen缓存，三次计时取每查询中位数，编码与证据核验不在其中。

SIGIR完整向量化扫描0.262ms，HNSW32为0.207ms，完整相似度前五专家全部保留、73/73条前五顺序相同，Soft/Hard P@5为0.4247/0.2027，与完整扫描相同。NIPS完整扫描1.343ms，HNSW32为0.661ms，完整前五专家平均保留99.41%、33/34条顺序相同，完整来源前十的集合包含率99.12%；但公开稀疏标签评测的Soft/Hard P@5由0.5412/0.2824降至0.4588/0.2529。HNSW128为2.122ms、完整前五候选全部保留，但Soft P@5仅0.5118；HNSW512为4.954ms、Soft P@5为0.5294。即使相似度全库前五保留，也可能漏掉仅在公开标注子集中排序较高的专家，二者不得混写为相关性召回率。精确来源检索Flat32同样降至Soft P@5=0.4647，表明主要损失也来自来源候选预算及标签候选协议，并非完全由HNSW近似造成。

评测明确只在实际召回专家中保留已标注者，缺失排名按P@5固定分母惩罚，不向榜尾追加未召回者；开发中发现追加负无穷分数的做法会在稀疏标注下虚增指标，已修正并重算全部107查询六种配置，上述仅引用修正结果。高来源保留率不等于高专家相关性精度，局部毫秒优化也不等于端到端agent加速。此成熟基线是后续新方法必须比较的对照，尚无跨两套数据同时加速且提高精度的结论。代码 `cof_hnsw.py`，依赖通过可选ann组安装；原始结果为 `cof-hnsw-sigir-v1`、`cof-hnsw-nips-v1`，含固定参数、Faiss版本、向量SHA256、索引构建时间/字节数及逐查询记录。


### 候选资格感知的来源扩展及选择性调度

进一步核对公开候选协议：SIGIR每查询的标注候选池为189人，NIPS仅1–17人，soft/hard候选ID相同。上一轮全库来源截断后再过滤候选，会把来源预算花在池外专家上。新增仅接受候选ID、不读相关性数值的扩展函数：从32来源起逐次加倍，直到恢复min(10,候选池人数)位合格专家或达到1024来源；不足目标则回退到候选池完整来源扫描。另以候选池的唯一来源数为选择性信号，≤1024来源直接扫描，否则采用扩展路径。此为成熟资格过滤、预算扩展与查询路径选择的组合基线，不宣称候选数停止构成排名证书，也不宣称新理论。资格池ID来自公开benchmark协议，在无给定资格池的真实企业搜索中不可由标注集合构造。阈值及协议属于查看早期失败后设计的探索，未用相关性数值挑选参数，仍非独立确认实验。

固定同一107条缓存查询、相同逐行FP32点积规则，完整全库、资格池完整、扩展、选择性切换均执行三次，交替正反运行顺序。四条路径在SIGIR73条及NIPS34条查询上的前五均与完整参考一致，Soft/Hard P@5分别保持0.4247/0.2027、0.5412/0.2824。SIGIR四路径均值为0.468/0.633/0.232/0.206ms；NIPS为1.958/0.322/1.474/0.296ms。共享候选ID和来源集合准备另为0.184/0.092ms，未包含在各路径局部计时中，不能把路径局部比值写成端到端加速。NIPS扩展发生3次完整扫描回退，选择性切换无回退；其直接资格扫描本来已足够快，切换不应声称相对这个强基线获得稳定大幅收益。近似扩展仍无排序保证，当前顺序一致只是这批查询的观察。

结果支持将资格选择性及归属关系显式纳入效率对照，也说明“始终使用ANN”不是最佳工程路径。保持冻结相似度的排序不等于提高企业需求证据精度；尚无新方法在端到端速度与精度上全面优于所有基线的证据。实现 `source_routing.py` 与 `cof_eligible_routing.py`，记录各次扩展深度、回退、候选数、唯一来源数、前五顺序与公开标签指标；工件 `cof-eligible-routing-{sigir,nips}-v1`。新增2项测试覆盖池外作者不能消耗合格专家预算、同一来源恢复多个合格作者以及预算耗尽显式返回。
