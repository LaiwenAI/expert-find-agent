# Aligning Experiments with the Continual Expert-Search Plan

The research plan prioritizes feedback-driven continual improvement of an expert-search agent under quality and cost constraints. Existing source ownership, evidence contracts, lexical and vector indexes, bilingual construction, and benchmark adapters remain the starting system and comparison infrastructure. Their previously reported retrieval or component results do not establish continual improvement.

## Current starting point

- The existing candidate and grounded pipelines provide frozen search, source access, and assessment paths. They do not yet provide an end-to-end feedback-driven policy update.
- The construction corpus has 1,000 real parent needs and 5,000 generated bilingual query pairs. Model screens are not independent expert-fit judgments; feedback, personal contribution, and genuine user outcomes remain unverified.
- Public reviewer ratings and EvidenceBench provide auxiliary evaluation. Reviewer ratings are not enterprise suitability labels, and model-assisted sentence aspects are not expert-level gold.
- Component timing and concurrent assessment pilots exclude parts of the agent. They are useful implementation baselines, not a full-agent quality or cost claim.

## Adjusted experimental sequence

1. **Freeze a static agent and strong retrieval baselines.** Version the corpus, source ownership, models, prompts, index, candidate and evidence budgets, failure policy, and timing scope. Include fixed lexical and dense ranking, a fixed agent, and direct feedback-free retrieval. Compare the same query cohort and report all attempts, unresolved outputs, initialization, query encoding, retrieval, reasoning, and total cost. Index changes require a separate arm.
2. **Build feedback and evaluation streams.** Keep existing construction, validation, and sealed company groups isolated. Preserve Chinese and English views of each parent together. For development, distinguish explicit corrections, exposure/choice events, and delayed outcomes. No actual user logs are presently established; synthetic feedback must be marked as simulated and assessed against independent labels when available. Do not treat unselected experts as negative or use the same model's generated feedback as gold.
3. **Compare feedback mechanisms.** Evaluate a frozen agent, a feedback-only correction or memory baseline, an adaptive-compute-only baseline, their simple combination, and a joint feedback-and-budget policy. Use the same model, snapshot, candidate pool where the causal question requires it, and feedback budget. Training-free memory/routing is the first comparison; RL, SFT or distillation remain later alternatives with their own training costs and data requirements.
4. **Test continual transfer and forgetting.** Fix update batches and order before evaluation. After each update, evaluate disjoint new tasks and a fixed old-task retention set; report quality per domain, need type, language and feedback availability. Hold the source index fixed when attributing gains to policy learning. Evaluate index updates separately. The 73-query simulation below does not satisfy this requirement.
5. **Measure quality, evidence and economics jointly.** Predefine expert-level success, source support, attribution, constraint satisfaction and unresolved outcomes using independent reviewers; treat missing information as unknown. Report P50/P95/P99 complete-query latency, token/API costs, failures, feedback, training, index and deployment amortization, and quality-cost curves. Set a meaningful non-inferiority margin before confirmation and use grouped paired uncertainty estimates; do not infer equivalence from an interval crossing zero.

## Initial feedback-route sanity check

`experiments.retrieval.cof_feedback_routing_simulation` replays previously explored CoF SIGIR rankings. In each of 30 shuffled streams, a simple epsilon-greedy selector receives only the chosen arm's reviewer-label P@5 after each query. Across overlapping 53-query post-warmup slices, mean soft P@5 is 0.412 for routing, 0.399 for fixed lexical, and 0.429 for fixed dense; dense is selected 58.7% of the time. These are simulated feedback on reused self-rated reviewer data, not user interactions or industrial labels. The shuffled streams are not independent or chronological; no real model call, latency, feedback collection, old-task retention, policy transfer, or training cost is measured. This is infrastructure exploration, not evidence of continual improvement.

## Immediate gates

- Do not claim improved enterprise precision, evidence correctness, contribution assessment, or quality-preserving speed until independent expert-level and source-level labels exist.
- Do not use held-out company groups to tune routing, feedback interpretation, stopping, or cost weights.
- Do not promote a simulated feedback policy to a user-facing default based on the replay above.
- Preserve negative and incomplete results; distinguish exposure, selected actions, missing labels, and eventual outcomes.

A follow-up `experiments.retrieval.cof_cost_feedback_replay` uses frozen single-query measurements that include live query encoding and scoring. An epsilon-greedy policy updates only from its chosen arm using reviewer-label soft P@5 minus a hypothetical penalty of five P@5 units per second; this exchange rate is not monetary or calibrated user utility. Across 30 overlapping 53-query post-warmup slices, routing, fixed lexical and fixed dense average P@5 0.417, 0.399 and 0.427, and recorded component times 10.49, 20.87 and 8.16 ms. The route chooses dense on 81.4% of evaluated queries. This simulation does not outperform fixed dense in these point estimates. GPU dense and CPU lexical use different hardware; each query has one prior measurement and the replay excludes initialization, reasoning, feedback acquisition, training, concurrency and serving. The reused, shuffled streams and reviewer self-ratings cannot establish enterprise quality, learning transfer, retention or full-agent cost. A cost-sensitive agent experiment must measure all of those separately and compare with fixed policies under identical conditions.

A further development-only pilot separates 73 previously explored CoF queries into 20 old-task, 20 feedback-update, and 33 new-task queries after grouping identical normalized title/abstract text. A fixed-seed cost-sensitive two-arm policy observes only selected-arm simulated feedback on the update fold; the old and new folds are used for descriptive evaluation at checkpoints. The lexical initial policy has old/new soft P@5 of 0.400/0.376. After five simulated updates the policy selects dense and stays there through 20 updates, giving 0.480/0.376, exactly the fixed-dense baseline on those folds. This is selection of an existing global arm, not demonstrated generalizable adaptation or a reduction in forgetting relative to a strong baseline. The split is post hoc, query text grouping does not establish task independence, reviewer labels simulate feedback, and timing is the earlier CPU/GPU component comparison with an arbitrary cost penalty. No genuine user feedback, independent enterprise labels, chronological stream, model training or full-agent cost is measured. Reproduce with `PYTHONPATH=src:. python -m experiments.retrieval.cof_retention_feedback_pilot`.

A contextual variant of the same split routes independently for queries at or below versus above 200 encoder tokens. This threshold was selected after inspecting the data; length is not a validated measure of task difficulty. After five simulated updates, the short bucket has no feedback and falls back to lexical while the long bucket selects dense. The resulting old/new soft P@5 is 0.420/0.339, below the fixed-dense 0.480/0.376; after 20 updates both buckets select dense and match that baseline. Only one lexical feedback observation is present in each bucket at that checkpoint. This exploratory single split is neither a controlled causal comparison nor evidence that all contextual routing fails. It illustrates why sparse feedback, cold-start defaults, bucket coverage, and old/new quality must be measured before allowing strategy updates. The same reviewer-label, previously explored data, artificial timing and task-dependence limitations apply. Reproduce with `PYTHONPATH=src:. python -m experiments.retrieval.cof_contextual_feedback_pilot`.

The experimental `FeedbackRouter` retains a caller-selected incumbent until every arm in a context has at least a specified number of observed outcomes; missing outcomes are not zeros, ties retain the incumbent, and contexts are isolated. It does not collect feedback, explore, correct selection bias, or offer statistical safety. A same-split replay uses the previously examined dense baseline and a post-hoc minimum of three observed outcomes per arm and bucket. At 5, 10 and 20 updates both buckets retain dense because lexical has only one observation per bucket; old/new P@5 remains 0.480/0.376, exactly the fixed dense baseline. This prevents the specific earlier switch by not updating the deployed choice, so it demonstrates neither learning gains nor a general quality guarantee. The incumbent, threshold and bucket were not selected on independent data; simulated feedback and test-fold caveats are unchanged. Reproduce with `PYTHONPATH=src:. python -m experiments.retrieval.cof_guarded_feedback_pilot`.

The experimental `FeedbackEvents` registry binds delayed outcomes to recorded context, selected arm and selection propensity. Repeating an identical exposure or completed outcome is idempotent; conflicting duplicates and unknown exposure IDs are rejected. Missing outcomes stay pending. It is an in-memory experimental registry, not a durable production log, and does not infer negative labels or correct selection bias. `experiments.retrieval.cof_logged_feedback_pilot` wraps the same simulated update stream and records all 20 exposures and outcomes, reproducing the previous guarded checkpoints. Logged propensities include deterministic initial actions, so overlap is not guaranteed; logging them alone does not validate inverse propensity scoring or causal policy evaluation. No genuine user feedback was collected.

The `offpolicy.evaluate` diagnostic requires full action-probability distributions, rejects missing outcomes and target actions with zero logging probability, and reports IPS, self-normalized IPS and effective sample size only when these input checks pass. These checks do not verify logged propensities, remove confounding, establish missing-at-random outcomes, or provide uncertainty intervals. Replaying the 20 simulated feedback updates with their full logging distributions identifies two deterministic lexical actions with zero probability of the fixed-dense target. The diagnostic withholds the fixed-dense estimate rather than computing an unsupported counterfactual. The existing synthetic data do not supply real user feedback or justify production policy evaluation. Reproduce using `PYTHONPATH=src:. python -m experiments.retrieval.cof_overlap_diagnostic`.

A controlled estimator sanity check samples 1,000 synthetic action logs from the same 73 frozen reviewer queries, with known constant dense-action probabilities 0.5 and 0.1 and complete simulated outcomes. The fixed-dense reviewer-label oracle is 0.422. IPS root-mean-square error across these repeated action draws is 0.056 at probability 0.5 and 0.166 at probability 0.1; mean effective sample size falls from 36.42 to 7.34, while maximum weights increase from 2 to 10. The draws reuse the same cohort and are not independent datasets; no real feedback, missingness, confounding, model uncertainty, monetary costs or expert-fit labels are modeled. This illustrates a variance cost of weak overlap under the constructed simulator, not validity of IPS on user logs. Reproduce with `PYTHONPATH=src:. python -m experiments.retrieval.cof_offpolicy_simulation`.

An initial correction-memory pilot simulates templated reviewer suggestions from the update fold: a reviewer in lexical top five, absent from dense top five, must have a positive public self-rating for that update query. A nearest-query TF-IDF memory can insert that reviewer into another query's dense top five when similarity exceeds 0.25. The textual template is stored but not parsed; this is a candidate-memory baseline, not natural-language feedback understanding. On the reused 20/20/33 old/update/new split, 16 simulated corrections lead to 10/16 actual insertions on old/new queries. Old soft P@5 changes on one query positively and none negatively; new changes positively on five and negatively on two, with mean differences +0.010/+0.018. These post-hoc point estimates neither establish transfer nor safety: the threshold and dataset were previously examined, profiles are not independently verified for the new query, labels represent reviewer self-ratings, and no real user correction, source support, personal contribution, or model call is measured. Reproduce with `PYTHONPATH=src:. python -m experiments.retrieval.cof_correction_memory_pilot`.

A post-hoc control permutes reviewer identities across the same 16 query-memory entries 1,000 times while retaining the query-similarity retrieval and threshold. On the 33 reused new queries, the original mapping's mean soft P@5 change is +0.018, versus a permutation mean of -0.003; 85 permutations match or exceed the original change. These permutations are repeated within one previously inspected dataset, not independent tasks or a causal significance test. Original identities were selected to be relevant to their own update queries, so permutation intentionally breaks that association. The feedback template is never parsed in either arm: this control does not test natural-language understanding. New-query source support remains unverified. Reproduce with `PYTHONPATH=src:. python -m experiments.retrieval.cof_correction_permutation`.

A post-hoc lexical-source gate was added to the simulated correction-memory replay: a proposed reviewer must have a positive BM25 paper score and rank among the top 50 reviewer profiles for the new query. On 33 previously explored new queries, ungated versus gated memory inserts 16 versus 7 candidates; relative to fixed dense, soft P@5 improves on 5 versus 2 queries and declines on 2 versus 0. On 20 old queries, inserts are 10 versus 8 and both arms improve one query. These are reviewer-level self-ratings, not source-support labels. The gate requires an additional full lexical scoring step: its local exploratory mean is 16.31 ms per attempted new-query insertion, excluding initialization and all other agent stages. It is neither a verified evidence-entailment test nor a demonstrated end-to-end speed or quality improvement. Thresholds and the cohort are post hoc; repeated queries and differing CPU/GPU measurements limit comparisons. Reproduce with `PYTHONPATH=src:. python -m experiments.retrieval.cof_memory_evidence_gate`.

A local alternative scores only the memory-proposed reviewer's papers using resident BM25 postings and accepts any positive match. Its scores match the global scorer for all 26 attempted old/new insertions, but this is a weaker decision rule than requiring a global top-50 position. On 33 reused new queries it admits all 16 proposed insertions, matching the ungated arm, including two decreases in reviewer P@5; the global gate admits seven. One sequential exploratory timing per insertion averages 0.444 ms for local scoring versus 15.63 ms for full lexical scoring plus owner ranking; local index initialization takes 89.37 ms separately. The different decisions, single machine, potentially warm cache, different operations and excluded end-to-end stages preclude a quality-preserving speed claim. Positive lexical overlap does not prove evidence support. Reproduce with `PYTHONPATH=src:. python -m experiments.retrieval.cof_memory_local_gate` using frozen public inputs.

A further exploratory candidate-threshold gate computes the proposed reviewer's exact BM25 score, uses upward-rounded per-term owner maxima to identify possible competitors, and scores those competitors exactly, retaining ties. The prototype expands each shared paper posting to every associated reviewer. On 26 attempted old/new insertions, its accept/reject decision matches the global top-50 rule. On the 16 new-query attempts, mean global scoring/ranking and bound-based decision times are 15.41 and 6.27 ms respectively; the latter still scores an average of 186.1 of 188 possible competitors. Resident index and bound construction take 91.49 and 32.03 ms separately. This is one sequential, potentially cache-affected measurement per attempt on a small public corpus; the two implementations perform different operations and exclude initialization, memory lookup, source reading and reasoning. It demonstrates agreement for this sample, not a general numerical certificate, semantic verification, enterprise quality, or end-to-end speedup. Reproduce with `PYTHONPATH=src:. python -m experiments.retrieval.cof_memory_certified_gate`.

The exploratory shared-source upper-bound gate is now factored into `SharedOwnerGate`. It rejects negative or nonfinite postings, assigns coauthored sources to every listed owner, conservatively includes score ties and retains upward rounding. Tests cover shared sources, tied scores, unknown sources, negative values and 50 small randomized posting sets compared exhaustively. A fresh public replay again matches the full top-50 decision on all 26 attempted old/new insertions; the 16 new-query attempts average 6.57 ms for the gate and 16.06 ms for full lexical scoring/ranking under the same sequential, cache-sensitive component measurement. This does not establish a general proof for arbitrary mutated indexes, semantic support, or production speed; resident index and ownership must remain immutable and validated externally.

A larger exploratory shared-owner check uses 30 previously available CoF NIPS queries, 364 reviewers and 14,913 unique source papers. For each query, candidates at full lexical ranks 10, 50 and 100 are selected before timing. Three alternating sequential measurements per case give 270 matching bounded-versus-full membership decisions. Mean full scoring/ranking versus bounded membership is 107.6/18.5 ms at rank 10, 107.3/18.5 ms at rank 50, and 108.7/18.5 ms at rank 100; resident and bound initialization separately take 685 and 164 ms. Candidate generation already performed full ranking and is excluded; the methods return different outputs, repetitions are dependent, and there is no separate warm-up or service load. Consequently these numbers neither show an end-to-end speedup nor establish source relevance or industrial fit. Reproduce with `PYTHONPATH=src:. python -m experiments.retrieval.cof_shared_gate_scale`.

A follow-up CoF NIPS component comparison includes the same cached-vector dense top-one candidate generation inside both timed arms, followed by full lexical top-50 membership or the bounded membership gate. On 30 previously explored queries with three alternating attempts each, all 90 candidate IDs and decisions match; mean times are 108.75 ms for dense-plus-full and 19.87 ms for dense-plus-bound on this local CPU setup. The bounded path still scores 286.3 possible competitors on average; resident and bound initialization take 676 and 172 ms separately. Query vectors are cached, the component output contracts differ, and source encoding, model reasoning, evidence reading, serving and concurrency are excluded. Repeats are dependent and there is no separate warm-up. This is a more complete component comparison than choosing candidates using untimed lexical ranking, not an end-to-end accuracy or latency result. A post-hoc label diagnostic on the same 30 reused CoF SIGIR queries examines whether the lexical rule itself discards relevant reviewers. Using cached CPU query vectors, the 50-candidate dense list has mean soft-label recall 0.253; filtering it through lexical top-50 membership reduces recall to 0.133 and returns 26.5 candidates on average. Hard-label recall changes from 0.258 to 0.136. At a budget of five, soft P@5 falls from 0.447 to 0.353 with a fixed denominator of five and no backfill. These results qualify the exact-decision timing result: equivalence to the lexical rule does not preserve dense retrieval quality. Labels are reviewer self-ratings, not enterprise suitability or source-level support; this is a reused cohort, a cached-vector diagnostic and not the live timing run. Investigate bounded backfill or selective gate application against an independent validation set before deployment. Reproduce with `PYTHONPATH=src:. python -m experiments.retrieval.cof_gate_budget_quality`.

A post-hoc backfill diagnostic on all 73 previously explored CoF SIGIR queries ranks dense candidates passing lexical top-50 first and appends rejected candidates in dense order. It preserves the complete candidate set, but changes its order. With a 10-candidate pool, soft P@5 is 0.433 versus 0.425 for dense; 15 queries improve, 14 worsen and 44 tie. With a 50-candidate pool, soft P@5 is 0.422 versus 0.425, with 15 improvements and 15 declines. At five candidates, both methods necessarily have identical P@5 because all five remain in the top five. These are reused reviewer self-ratings, no independent test or source support, and no timing; simple backfill alone is not established as a quality improvement. Reproduce with `PYTHONPATH=src:. python -m experiments.retrieval.cof_gate_backfill_quality`.
