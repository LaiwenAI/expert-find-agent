# Feedback-driven expert search: proposed evaluation protocol

**Status: design proposal, not a preregistered or completed study.** Existing CoF simulations use reviewer self-ratings, not actual corrections. In particular, the current correction-memory pilot associates a query with a reviewer ID and never parses its feedback sentence. Its permutation control tests the association between the query and ID; it cannot establish understanding of natural-language feedback. `FeedbackEvents` is an in-memory prototype and does not provide durable logs or correct selection bias.

## Research questions and fixed comparison arms

1. Does feedback improve expert ranking or evidence support on new needs over a frozen agent with the same underlying corpus, model, source views and compute budget?
2. Does a correction's content add value beyond storing an expert identity, and does updating a policy harm previously served needs?
3. What quality, latency and monetary trade-offs arise after including feedback acquisition, index maintenance, and updates?

Freeze the implementation, prompts, candidate pools, budgets and failure policy before the confirmatory evaluation. Compare: (A) fixed dense and fixed lexical baselines; (B) a static grounded agent; (C) identity-only query memory; (D) the same memory with correction text parsed into structured aspects and citations; (E) adaptive-compute-only; (F) a simple combination of feedback memory and adaptive compute; and (G) the proposed joint policy. The text arm must be a real implementation: persist the parsed content and record whether it changed the ranking or evidence. Until then, D and G are planned arms, not implemented results. Include a text-swap control that pairs correction content with another update case while retaining candidate identities, and an identity-swap control that retains text while swapping candidates. Both can create incoherent pairs; report them as diagnostic interventions rather than realistic user feedback. All arms receive the same exposed feedback cases and resource budget where applicable.

## Structured-feedback prototype

`expert_search.feedback_content` provides an experimental deterministic application step for already structured corrections: the expert must occur in the candidate ranking, the named query phrase must occur in the query, and the exact quoted text must appear in a source assigned to that expert. Matching promote or demote actions change the stable ordering; conflicting actions abstain. This validates neither semantic entailment nor ownership metadata, and it does not parse free text, retrieve sources, learn from feedback, or establish a quality improvement. `tests.test_feedback_content` exercises changed scope and quote, absent ownership and conflicts using handcrafted cases. The proposed text-parsing and joint-policy arms remain unimplemented.

## Data, independence and events

Partition by company and near-duplicate need clusters before choosing policies or prompts. Keep all translations and synthetic children with their parent. Use separate development, policy-selection, and sealed evaluation partitions, with domain and language coverage recorded; preserve a fixed old-task panel and a disjoint new-task panel. Choose panel sizes and a defensible non-inferiority margin before unsealing, based on the minimum useful effect and available independent groups; do not invent a power claim. Lock the list of hypotheses, primary metric, multiplicity handling, update schedule, cost convention and analysis code before labels are revealed. Save versioned hashes and timestamp the lock; a proposed protocol alone is not preregistration.

First use simulated corrections to test data flow, including absent, delayed, contradictory and wrong feedback. Simulated labels must be tagged and must not serve as gold. For a real study, collect explicit natural-language corrections and separately capture exposure, rank, click or selection, and later outcomes with timestamps, source snapshots and permission. A click or selection is not proof of ability, and an unselected expert is not a negative label. Log the probability of each actual routing action and all candidate exposures. Missing outcomes remain pending. Use randomized exploration only with an explicitly specified deployment policy; off-policy estimators require overlap and a justified missingness model, neither of which is supplied by logging propensity alone. Record privacy and release permissions; keep private source text and identifiers local until authorized.

## Independent judgments and analysis

For a frozen pooled set of candidate/source views, obtain two independent qualified reviewers' judgments on method fit, stated constraint support, and personal contribution, with unknown and not-supported-by-view kept distinct. Hide method and rank where possible, document that source content can reveal identity, adjudicate disagreements with a third reviewer, and report agreement, missingness and adjudication. Include random additional candidates to measure pooling blind spots. Use existing `check_joint_review`, `reconcile_joint_review` and `overlay_joint_sample` tools for their documented fixed-view workflows; no human gold currently exists. Unjudged or unresolved cases remain unknown, with identification bounds or sensitivity analysis reported rather than imputed negatives.

Choose one primary expert-level metric and a separate evidence-support metric in the registered analysis; include P@5, graded nDCG, source-support precision and unknown/unresolved rates as secondary measures. Compare paired differences against the fixed agent and identity-only memory, with company/near-duplicate group bootstrap or a suitable clustered design. Report groups, queries, feedback cases, per-domain and per-language outcomes, missingness and uncertainty. Compare each update checkpoint with the same frozen old panel and a disjoint new panel; report changes from the pre-update baseline and fixed-agent comparator. A random partition labelled old/new is not a temporal forgetting experiment.

Measure complete query wall time, P50/P95/P99, failures, queueing, token usage and API cost under a declared workload. Separately report one-time and recurring costs of indexing, feedback review and policy updates, plus their amortization assumptions. For quality–cost curves, fix budgets before evaluation; assess non-inferiority only against a prespecified margin using the appropriate one-sided confidence bound. Do not combine unlike CPU/GPU component timings as end-to-end savings.

## Promotion gate

Do not deploy an adaptive policy based on these simulations. Advance to a confirmatory comparison only after frozen data partitions, independent judgments, operational feedback logging, predefined statistical criteria and complete cost measurement are available. If those prerequisites are missing, continue treating the results as development evidence and publish their limitations.
